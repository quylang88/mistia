# Ordinary wallet protection around investment cash

Swift ManagementEditors.swift447/719/767 refuses type/currency changes and archive while the wallet is linked or has a nonzero signed total of alive cash-location postings. Android now evaluates that business rule inside Room's existing local mutation transaction before wallet or outbox writes. The current stored wallet determines whether a financial shape/archive change needs the check; name/icon and opaque metadata edits remain allowed. Restoring an archive does not create a new archive restriction. The deterministic reserved root keeps its existing dedicated repair/publication path.

The guard reads only the selected owner's wallet and posting partition. Canonical body/envelope identity, consistent tombstones, readable root links and cash metadata are required to prove the wallet is unlocked. Live legacy noncash FIFO rows do not count; alive cash metadata in both booked and unreconciled buckets does. Exact BigInteger signed totals avoid Int64 overflow; separate accounting currencies never cancel. Nonzero negative totals remain protected, matching the Swift condition. Other wallets and owner partitions do not lock this wallet. Invalid source data holds the change through the existing stale-edit error.

Room checks the active owner and caller before the source read and after both local writes. A late link or cash posting arriving after the repository's wallet read therefore still blocks the commit. A rejected row rolls back an entire enclosing batch. Existing live-ledger currency checks, no-opening-money rewrite, credit-card aggregates and root metadata code remain; no generic remote writer, SQL/RLS policy or write gate changes. The shared UI mapper uses existing investment.error.walletHoldsCash for the new typed protected error on save/archive, retains currency-history errors and each editor's generic fallback, and keeps the draft open.

The scope is local validation/error parity. Pending confirmed transfers and linked-wallet-move/allocation publication remain subsequent work. This rule matches current cash state; it does not claim an atomic server ledger+posting transaction or all wallet retirement coordination is solved. No Samsung/live Supabase/production write/deploy/push is authorized by this slice. Full APK1–4/RC remains active.

Two older Investment tests must still exercise legacy pending archives and an already changed accounting source. Their fixtures now rehydrate those existing Room/outbox states through an internal AndroidTest-only helper; production mutation methods enforce the new guard. No runtime validation bypass is shipped.
