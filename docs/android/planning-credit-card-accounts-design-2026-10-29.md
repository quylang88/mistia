## Approaches and chosen structure

Chosen: add a complete owned three-domain read snapshot (wallet/profile/ledger), a pure account projection and focused Planning pane; reuse the established Management CreditCardEditorSheet through an owner-scoped route/controller and wire actual app navigation to existing statements/new editor. This preserves exact money and existing form validation without production peer-module dependencies. A combined set of independent flows can briefly mix account generations; a single DAO query avoids that. Duplicating the card form in Planning would drift from the established currency/source/save rules, so it is rejected. These choices follow the user's parity/continuous-execution direction.

## Read and projection contract

New `CreditCardAccountReadSnapshot(owner:UserId,rows:List<CloudRecord>)`, domains wallet/profile/ledger, reads all owned rows including tombstones/history in one Room query. Add `observeCreditCardAccountReadSnapshot(owner):Flow<CreditCardAccountReadSnapshot>` to FinanceRepository/LocalStore and actual Room/repository delegation; unsupported implementations fail explicitly. No schema migration. Validate envelope/body owner/ID/entity/birth/version and duplicate identities before projection, with no successful partial account list from malformed relevant data. Rendering is read-only and never creates/deletes/ACKs outbox entries.

`planningCreditCardAccounts(snapshot):List<PlanningCreditCardAccount>` joins exactly one live owned profile per active non-system credit-card wallet. Exclude deleted/archived card wallets, deleted profiles, foreign rows and orphan profiles. An ambiguous live profile link is an explicit read error. Use established TransactionWalletBalanceIndex over owned posted, nondeleted/nonarchived transactions, preserving destination amounts and debt semantics; ignore wallet cached balance and credit-card opening balance as Swift does. Debt=max(balance,0), available=max(limit-debt,0), numericLong with no Float/Double or primary-currency conversion. Sort by persisted wallet sortOrder, then stable creation/id ordering. Current amounts do not change with Planning month or selected primary currency. Linked source names must come only from owned live ordinary non-system wallets; missing/deleted/foreign source shows localized no-linked-wallet text. Retained archived source metadata may label history but never authorizes a payment. Network unknown→Other, mask at most last4 and never expose longer input.
